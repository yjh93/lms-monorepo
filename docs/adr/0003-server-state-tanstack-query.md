# ADR 0003. 서버 상태는 TanStack Query 중심으로 둔다

- 상태: 채택
- 날짜: 2026-10-16

## 맥락

어드민 상태는 성격이 다른 세 종류가 섞여 있다.

| 종류            | 예                                      | 특징                                 |
| --------------- | --------------------------------------- | ------------------------------------ |
| 서버 상태       | 수강생 목록, 수업 출석부, 대시보드 집계 | 원본은 서버, 캐시·재요청·무효화 필요 |
| URL 상태        | 목록의 페이지·정렬·필터                 | 새로고침·공유·뒤로가기에 유지돼야 함 |
| 클라이언트 상태 | 로그인 사용자, 분석 화면 필터           | 브라우저 안에서만 의미 있음          |

## 결정

- **서버 상태 → TanStack Query.** query key factory와 `queryOptions`로 키·요청 함수·타입을 한 곳에 묶는다.
- **URL 상태 → URL 쿼리.** zod 스키마로 파싱·직렬화하고 TanStack Query 키로 그대로 쓴다(수강생 목록, 변경 이력).
- **클라이언트 상태 → Zustand.** 로그인 사용자(React 밖 API 헤더·401 처리에서도 접근), 출석 분석 필터(탐색 중 자주 바뀌는 일시 상태).

## 근거

- 서버 데이터를 전역 스토어에 복사하면 로딩·에러·캐시 만료·재요청을 직접 구현하게 되고 원본과 사본이 어긋난다. TanStack Query는 이를 캐시 키 단위로 관리한다.
- 변경 후 무효화를 범위 단위로 할 수 있다: 수강생을 수정하면 `studentKeys.lists()`, 고객사 목록, 대시보드, 감사 로그를 함께 무효화한다.
- `placeholderData: keepPreviousData`로 페이지 전환 중 이전 결과를 유지해 테이블이 깜빡이지 않는다.
- 4xx는 재시도하지 않고, 401은 `QueryCache.onError`에서 로그아웃 처리한다.
- **Web Worker도 같은 모델로 다룬다**: 출석 분석의 워커 RPC를 queryFn으로 감싸 필터 조합별 집계를 캐시하고, 커서 기반 목록은 `useInfiniteQuery`로 받는다.

## 결과

- 낙관적 업데이트는 두 방식을 쓴다: 출석 체크는 React 19 `useOptimistic`(화면 단위, 자동 롤백) + 성공 시 `setQueryData`로 확정 → [ADR 0005](0005-react-19-features.md)
- 로그인·로그아웃 시 `queryClient.clear()`로 이전 사용자의 캐시를 비운다.
- 학습자 사이트(Next.js)는 서버 컴포넌트에서 데이터를 읽으므로 TanStack Query를 쓰지 않는다. 캐시는 Next의 `'use cache'`가 맡는다.
