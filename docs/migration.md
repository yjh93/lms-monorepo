# 레거시 Vue 어드민 → React 어드민 점진적 마이그레이션

`apps/legacy-admin`(Vue 3)은 기존 운영 어드민이 Vue로 만들어져 있다는 전제의 축소판이다. 수강생 목록 한 화면만 있고, 같은 화면이 React 어드민(`apps/admin`의 `/students`)에도 있다. 한 번에 다시 만드는(big bang) 대신 화면 단위로 옮기는 전략과, 이 저장소에서 그 전략이 코드로 어떻게 드러나는지 정리한다.

## 원칙

1. **공유 계층부터 프레임워크 밖으로 뺀다.** API 호출, 응답 검증, 폼·쿼리 규칙, 권한, 디자인 토큰은 Vue/React 어느 쪽에도 묶이지 않게 만든다.
2. **화면 단위로 옮긴다(strangler fig).** 라우트 하나씩 React로 넘기고, 넘어간 경로만 새 앱이 받는다.
3. **같은 입력에 같은 결과를 보장한다.** 옮긴 화면이 기존 화면과 같은 URL에서 같은 데이터를 보여주는지 테스트로 확인한다.
4. **언제든 되돌릴 수 있게 한다.** 경로 전환을 배포와 분리한다(라우팅 설정·플래그).

## 1단계: 공유 계층 분리 (이 저장소에서 완료)

| 공유 대상          | 위치                                                  | 레거시 Vue에서의 사용                        |
| ------------------ | ----------------------------------------------------- | -------------------------------------------- |
| API 함수·응답 검증 | `@lms/api-client` 기본 엔트리                         | `fetchStudents`를 그대로 호출                |
| URL 쿼리 규칙      | `parseStudentListQuery` / `toStudentListSearchParams` | Vue composable이 같은 함수로 URL ↔ 상태 변환 |
| 표시 규칙          | `STUDENT_STATUS_LABEL`, `LEVEL_LABEL`, `formatPhone`  | 템플릿에서 그대로 사용                       |
| 권한               | `@lms/utils`의 `can()`                                | (이 화면은 조회만이라 미사용)                |
| 디자인 토큰        | `@lms/config/tailwind/theme.css`                      | 같은 색·라운드·폰트                          |
| 목 서버            | `@lms/api-client/mocks`                               | 같은 MSW 핸들러로 개발·테스트                |

`@lms/api-client`를 엔트리별로 나눈 이유가 여기 있다. Vue 앱은 기본 엔트리만 import하므로 React Query나 React 코드가 레거시 번들에 섞이지 않는다.

결과적으로 두 화면은 **같은 URL(`?status=PAUSED&page=2`)이면 같은 요청을 보내고 같은 결과를 보여준다.** 레거시 테스트(`useStudentList.test.ts`)와 React 테스트(`StudentListPage.test.tsx`)가 같은 규칙을 검증한다.

## 2단계: 화면 단위 전환

운영 환경에서는 같은 도메인 아래에 두 앱을 두고, 리버스 프록시(또는 CDN 라우팅)로 경로별로 보낸다.

```
/admin/students          → React 어드민   (전환 완료)
/admin/students/*        → React 어드민
/admin/lessons           → 레거시 Vue     (전환 전)
/admin/*                 → 레거시 Vue     (기본값)
```

화면 하나를 옮기는 순서:

1. React 어드민에 같은 화면을 만든다. 공유 계층을 쓰므로 데이터·규칙 코드는 새로 쓰지 않는다.
2. **동등성 테스트**: 같은 시나리오(필터·정렬·페이지 이동)를 두 화면에 돌려 결과를 비교한다. 이 저장소에서는 두 화면의 URL 규칙과 요청을 같은 함수가 만들기 때문에, 단위 테스트와 E2E로 이를 보장한다.
3. 일부 사용자(예: 내부 운영자)에게만 새 경로를 열고(플래그·쿠키 기반 라우팅), 오류율·사용성 피드백을 본다.
4. 기본 라우팅을 새 앱으로 바꾼다. 문제가 생기면 라우팅만 되돌린다.
5. 레거시 화면 코드를 삭제한다.

## 3단계: 화면 간 이동과 상태

- **인증**: 두 앱이 같은 세션(쿠키)을 읽게 한다. 이 저장소의 데모는 앱마다 목 로그인을 쓰지만, 실제 전환에서는 인증을 앱 밖(게이트웨이·공통 쿠키)에 둔다.
- **화면 간 링크**: 앱 경계를 넘는 이동은 일반 `<a>`(전체 페이지 이동)로 한다. 같은 앱 안에서만 클라이언트 라우팅을 쓴다.
- **공통 레이아웃**: 전환 기간에는 헤더·메뉴가 두 벌이다. 메뉴 정의(경로·권한)를 공유 데이터로 빼 두면 두 앱의 메뉴가 어긋나지 않는다.

## 옮기는 순서 정하기

| 우선 옮길 화면                      | 이유                                                     |
| ----------------------------------- | -------------------------------------------------------- |
| 변경이 잦은 화면                    | 새 구조의 이득(테스트·타입·공유 스키마)을 가장 빨리 본다 |
| 공유 계층으로 거의 덮이는 조회 화면 | 위험이 낮아 첫 사례로 적합(이 저장소의 수강생 목록)      |
| 레거시에서 버그가 많은 화면         | 옮기면서 고친다                                          |

| 나중에 옮길 화면                        | 이유                         |
| --------------------------------------- | ---------------------------- |
| 거의 바뀌지 않는 설정 화면              | 이득이 작다                  |
| 레거시 전용 라이브러리에 깊이 묶인 화면 | 대체 구현과 검증 비용이 크다 |

## Vue → React 대응표 (이 화면 기준)

| Vue (legacy-admin)                                   | React (admin)                                                 |
| ---------------------------------------------------- | ------------------------------------------------------------- |
| `reactive(query)` + `watch` → `history.replaceState` | `useSearchParams` + 파생 상태(`useMemo`)                      |
| composable `useStudentList()`                        | 커스텀 훅 `useStudentListParams()` + `useStudents()`          |
| 수동 `AbortController`, `loading`/`error` ref        | TanStack Query(취소·로딩·에러·캐시·이전 데이터 유지)          |
| `v-for` 테이블                                       | `@lms/ui` `DataTable`(TanStack Table, 서버 정렬·페이지네이션) |
| 직접 만든 디바운스                                   | `useDebouncedCallback`                                        |

레거시 쪽 상태 관리 코드(요청 취소, 로딩·에러 처리)가 React 쪽에서는 TanStack Query 한 줄로 바뀌는 것이 이 전환에서 얻는 가장 큰 이득이다. 반대로 데이터 규칙은 이미 공유 계층에 있으므로 옮기면서 다시 쓰지 않는다.
