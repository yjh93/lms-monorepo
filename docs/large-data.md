# 대용량 출석 분석 (`/analytics`)

최근 1년 출석 기록 30만 건을 브라우저에서 필터링·집계·정렬하고, 차트와 가상 스크롤 목록으로 보여준다.

## 구조

```
메인 스레드                                   Web Worker
───────────────────────────────              ─────────────────────────────────
Zustand (필터·정렬·히트맵 선택)
   │
TanStack Query ── useQuery(aggregate) ──▶ postMessage ──▶ createAnalyticsService
               └─ useInfiniteQuery(rows) ─▶             ├─ generateDataset (열 단위 TypedArray)
   │                                                     ├─ filterIndices  (정수 비교 루프)
차트(히트맵·월별·고객사) / 가상 스크롤 목록 ◀── 결과 ◀──   ├─ aggregate      (단일 패스 집계)
                                                         └─ sortIndices + 커서 페이지
```

- **데이터 보관**: 레코드를 객체 배열이 아니라 열마다 `Int32Array`/`Uint8Array`/`Uint16Array`로 보관한다. 30만 건이 3.7MB다(같은 데이터를 객체 배열로 들면 수십 MB).
- **Web Worker**: 생성·필터·집계·정렬을 전부 워커에서 처리한다. 메인 스레드는 결과만 받아 그린다.
- **TanStack Query로 워커 감싸기**: 워커를 원격 서버처럼 다룬다. 필터 조합별로 집계 결과가 캐시되고, 목록은 커서 기반 `useInfiniteQuery`로 200건씩 받는다.
- **Zustand**: 필터·정렬·히트맵 셀 선택은 탐색 중 자주 바뀌는 일시적 상태라 URL 대신 Zustand에 둔다. 컴포넌트는 필요한 조각만 구독한다(공유가 중요한 수강생 목록은 URL을 상태 저장소로 쓴다).
- **가상 스크롤**: TanStack Virtual로 보이는 행(+여유분)만 DOM에 그린다.
- **교차 필터**: 히트맵 셀을 누르면 해당 요일·시간대로 KPI·차트·목록이 함께 필터링된다. 히트맵 자체는 셀 필터 적용 전 집합으로 계산해 다른 셀을 계속 고를 수 있다.

## 측정 (2026-10-30, 개발 PC)

| 항목                                                     | 결과  |
| -------------------------------------------------------- | ----- |
| 데이터셋 생성 (30만 건, 워커)                            | 105ms |
| 메모리 (열 단위 TypedArray 합계)                         | 3.7MB |
| 필터 + 집계, 최근 90일                                   | 18ms  |
| 필터 + 집계, 최근 1년                                    | 37ms  |
| 1년 전체를 이름순 정렬 (최초 1회, 이후 같은 조건은 캐시) | 260ms |
| 7만여 건 중 1,400건까지 스크롤했을 때 DOM 행 수          | 37개  |

개선 기록

- 처음에는 월별 집계에서 레코드마다 `Date`를 만들어 월 문자열을 구했다(최초 집계 457ms). 날짜(일 수) → 월 버킷을 한 번만 계산해 재사용하도록 바꿔 18~37ms로 줄였다.
- 정렬은 문자열 비교 대신 이름을 미리 순위(정수)로 바꿔 비교한다. 정렬은 워커에서 실행되고 같은 필터·정렬 조합은 재사용하므로, 다음 페이지를 불러올 때는 다시 정렬하지 않는다.
